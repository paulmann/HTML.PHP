# v4.0.0 Architecture (binding decisions)

## Layer map

```
Layer 0  Support      Str, Num, Arr, Pcre, Clock, Uuid          (pure static, no state)
Layer 1  Contracts    Config, Container, *Interface, enums      (no behaviour, no I/O)
Layer 2  Infra        Io\{Files,AtomicWriter,PathGuard}, Html\{Escaper,Cleaner},
                      Cache\{File,Apcu,Array,Null}, Log\{File,Syslog,Null,Array},
                      Event\Dispatcher, Diagnostics
Layer 3  Domain       Ssi\{Processor,Context,Expression,Exec,Directives\*},
                      I18n\{Translator,Catalog,PluralForms,Locale},
                      Template\{Resolver,Substitution,Filters,Loops,Conditionals,Renderer}
Layer 4  Facades      Engine, WordPress\Bridge, WordPress\Maintenance\*
```

Rule: a layer may depend on lower layers only. Nothing reads `$GLOBALS`,
`$_SERVER`, `$_GET/POST/COOKIE`, `getenv()` or `php_sapi_name()` below Layer 4.
Host state enters **once**, through explicit constructor arguments.

## Replacing $GLOBALS

v3 kept ~35 `$GLOBALS['HTML_*']` keys as the source of truth. v4 deletes all of them:

| v3 | v4 |
|---|---|
| `$GLOBALS['HTML_*']` + `Config::limit/flag/str` statics | immutable `Config` value object (nested readonly groups), built by `ConfigBuilder` |
| `Errors::add()` static registry | injected `Diagnostics` (+ `LoggerInterface`) |
| `Hooks::` static filter/action registry | injected `Event\Dispatcher` |
| `Filters::$custom` static | injected `Filters` instance |
| `Translator::` static catalogues/locale | injected `Translator` instance |
| `Cache::` static file cache | injected `CacheInterface` |
| `update_template()` reading `$GLOBALS[$name]` | `Resolver` over an explicit `Scope` only |
| `$_SERVER['DOCUMENT_ROOT']` inside SSI | `RequestContext` value object passed to `Engine::render()` |
| `$_GET/$_POST/...` sanitising helper | `Input::fromSuperglobals()` — the *only* place that touches them, called by the host |

`Config` is immutable: `with*()` methods return clones. `Container` wires
singletons lazily; `Engine::create(Config $config, ?Container $container = null)`.

## Template syntax (v4)

Kept from v3 (users' templates keep working): `%{NAME}`, `#{NAME}`, `@{KEY}`
(translation), `%{NAME|filter:arg}`, `<!--@Loop rows-->`, `<!--@If flag-->`,
`<!--@Else-->`, all Apache SSI directives.

Dropped (legacy html4.pl): `%[NAME]`, `%{%{NAME}}`, `.Round/.Div/.Clean Round`
numeric directives, `<!--@Block NAME-->`, `<!--@Split-->`, `Read_HTML`, `Show_HTML`.

New in v4 (see `06-GAPS.md` for rationale):
- `<!--@If EXPR-->` with a real expression language (`a.b > 3 && !(c || d)`),
  `<!--@Elif EXPR-->`, `<!--@Unless EXPR-->`
- `<!--@Extends "layout"-->` + `<!--@Block name-->` inheritance with `parent()`
- `<!--@Partial "card" with="a,b" only-->` scoped includes
- `<!--@Set name="expr"-->`, `<!--@Raw-->…<!--@EndRaw-->`, `<!--@Comment-->`
- `<!--@Empty rows-->` fallback for empty iterables, `<!--@Break-->`/`<!--@Continue-->`
- loop context object `loop.index/first/last/length/parent`, range loops `1..10`
- strict mode: unknown filter / missing var / unclosed tag become exceptions
  instead of silent diagnostics
- `{NAME}` single-brace form off by default, opt-in via config (avoids CSS clashes)

## SSI

`Ssi\Processor` becomes **instance-based**, driven by a `DirectiveRegistry`.
Every directive is its own class implementing `DirectiveInterface`
(`name()`, `render(array $attrs, SsiContext $ctx): string`), so hosts can add or
override directives without touching the scanner. `#if` frames move into the
processor as an immutable value stack.

## Editions

`src/` is the PHP 8.3 source of truth. `php85/html.php` is generated by
`tools/build.php` (rewritten from v3's Python) which:
1. concatenates `src/**/*.php` in dependency order into one file,
2. swaps in the whole-file 8.5 overlays from `src-8.5/`
   (property hooks, asymmetric visibility, pipe operator, `array_find`/
   `array_last`, `#[\NoDiscard]`, typed class constants),
3. asserts every overlay applied (fails the build on drift),
4. writes both `php83/html.php` and `php85/html.php` with a version guard.

Both bundles must pass the same test matrix.
